# To-Do List on Any Device Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Work tab with a to-do list that the owner uses from PC and phone, stored in a private GitHub repo, with Claude posting suggestions each weekday morning.

**Architecture:** The page becomes a static site on GitHub Pages. A small storage module reads and writes two JSON files in the private repo `KyloKen1/journal-data` through GitHub's Contents API, using the file `sha` for conflict detection. Claude's skills reach the same files through a small Python tool that wraps `gh api`.

**Tech Stack:** Plain JavaScript ES modules (no framework, no build step), CSS grid, GitHub Contents API, GitHub Pages via Actions, Python 3.13 standard library + `gh` CLI for the skills' tool.

**Spec:** `docs/superpowers/specs/2026-11-11-todo-design.md`

## Global Constraints

- No third-party scripts, fonts or styles. No Node, no build step.
- Network requests from the page go only to `https://api.github.com`.
- Data repo: `KyloKen1/journal-data`, files `journal.json` and `suggestions.json`, JSON written with 2-space indent.
- Token lives only in `localStorage` under the key `journal.githubToken`.
- Claude's skills never write `journal.json`, except `update-wishlist` saving `Want:` / `Budget:` lines.
- Autosave debounce 3000 ms; retry every 10000 ms.
- User-facing messages are copied exactly from spec section 7.
- All work happens on a branch named `todo`; `main` keeps the working local app until Task 7 merges.
- Browser tests are HTML pages in `web/test/` that print `All N passed` or `FAIL <name>` lines into `<pre id="out">`, in the style of `web/test/save-test.html`. Run them with `python -m http.server 8766 --directory web` and open `http://localhost:8766/test/<page>` in the Browser pane.
- Every commit message ends with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. Text with accents or emoji in a title or description must survive save and load unchanged (base64 of UTF-8, not of UTF-16). Test in Task 1.
2. `journal.json` still in the old shape (`issues`, `version`) or not valid data: old shape converts on load; anything else leaves the page read-only and is never overwritten. Tests in Task 2, behaviour in Task 4.
3. `suggestions.json` missing the `todos` key, or holding suggestions for an item that was deleted or completed: the page shows nothing for them and does not crash. Test in Task 2.
4. An item created at 23:59 yesterday counts as carried over 1 day; day counts are by local calendar date, including across a month end. Test in Task 2.
5. A token pasted with spaces or a trailing newline is stored trimmed; an empty one is refused. Test in Task 4.

## Deviations from the spec (spec is updated in Task 7)

- Work cards are converted by the page the first time it loads old-shape data, not by a one-off script. The cutover only uploads the existing file. This keeps one tested copy of the conversion.
- A small `tools/data.py` with its own unittest file is added for the skills, so `tests/` is not removed entirely.
- GitHub answers 404 when a token cannot see the private repo, so 404 is treated like 401/403 (token not accepted).

### Task 2: To-do model

**Files:**
- Create: `web/todo-model.js`, `web/test/todo-model-test.html`

**Interfaces:**
- Consumes: `newId`, `nowISO`, `todayISO` from `web/format.js`.
- Produces (all exported from `web/todo-model.js`; dates are `"YYYY-MM-DD"`, timestamps `"YYYY-MM-DDTHH:MM:SS"` local time):
  - `convertIssue(issue) -> todo` per the spec's conversion table.
  - `normalizeJournal(data) -> { todos, wishlist }`. Accepts `{ todos: [], wishlist: [] }` as is; converts `{ issues: [], wishlist: [] }`; drops `version`; throws `Error` for anything else.
  - `normalizeSuggestions(data) -> { items: {}, todos: {} }`. Missing or non-object keys become `{}`; a non-object `data` gives both empty.
  - `newTodo(title, now) -> todo` (empty description, upNext, progress; `completed: false`, `completedDate: null`; `created` and `updated` = `now`).
  - `carriedOverDays(todo, today) -> number` — whole calendar days from the date part of `todo.created` to `today`, never below 0.
  - `openTodos(todos) -> todo[]` — not completed, oldest `created` first.
  - `completedTodos(todos) -> todo[]` — completed, newest `completedDate` first.
  - `completeTodo(todo, today)`, `reopenTodo(todo)` — set / clear `completed` and `completedDate`.
  - `completeStep(todo, step, today)` — removes `step` from `upNext`, puts `{ id, text, date: today }` at the front of `progress`.
  - `applySuggestion(todo, entry, suggestionId) -> boolean` — appends each of the suggestion's `steps` to `todo.upNext` as `{ id: newId(), text }`, removes the suggestion from `entry.suggestions`; `false` if the entry or suggestion is missing.
  - `removeSuggestion(entry, suggestionId)` — removes it if present; tolerates `entry` being `undefined`.
  - `dismissSuggestion(entry, suggestionId)` — removes it and appends its `text` to `entry.dismissed`, keeping the last 10; tolerates a missing entry or suggestion.
  - `pendingSuggestions(todo, todoSuggestions) -> suggestion[]` — `[]` when the todo is completed or has no entry.

### Task 3: Saving through storage

**Files:**
- Modify: `web/save.js`, `web/suggest.js`, `web/test/save-test.html`, `web/test/suggest-test.html`
- Create: `web/suggest-store.js`, `web/test/suggest-store-test.html`

**Interfaces:**
- Consumes: `StorageError`, storage `load` / `save` (Task 1); `normalizeSuggestions`, `removeSuggestion`, `dismissSuggestion` (Task 2).
- Produces:
  - `createSaver({ save, onStatus, debounceMs = 3000, retryMs = 10000 })` where `save(): Promise<void>` throws `StorageError`. Returns `{ changed(), isIdle(), resume() }`.
    `onStatus(status, error?)` with status `"saving" | "saved" | "conflict" | "auth" | "offline" | "error"`:
    - `conflict` → stops for good (as today).
    - `auth` → pauses with the edit still pending, no retry timer; `resume()` saves again.
    - `offline` (kind `"offline"`) and `error` (kind `"http"`, passes the error so the caller can show `status`) → retry every `retryMs`.
  - `createSuggestionStore({ storage, path })` returning
    `load(): Promise<{ items, todos }>` (remembers the sha) and
    `update(mutate): Promise<boolean>` — applies `mutate(data)` to its current copy and saves; on a `"conflict"` it reloads, applies `mutate` again and saves once more; returns `false` on any other failure or a second conflict. `mutate` must be safe to run twice.
  - In `web/suggest.js`: `initSuggestions(store)` replaces the `fetch` calls. `loadSuggestions()` and `dismissSuggestions(itemId)` keep their names and return types (`items` map; boolean) but go through the store. Add `todoAcceptedQueue = createDismissQueue(removeTodoSuggestion)` keyed by `` `${todoId}/${suggestionId}` ``, and `dismissTodoSuggestion(todoId, suggestionId): Promise<boolean>`.
